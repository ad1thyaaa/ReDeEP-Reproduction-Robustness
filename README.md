# ReDeEP: Reproduction and Robustness Study

IOE-414 Deep Learning minor project, IIIT Kottayam — Gourilakshmi S and Adithya K.

Reproduction of *ReDeEP: Detecting Hallucination in Retrieval-Augmented Generation via
Mechanistic Interpretability* (Sun et al., ICLR 2025;
[arXiv:2410.11414](https://doi.org/10.48550/arXiv.2410.11414);
[official code](https://github.com/Jeryi-Sun/ReDEeP-ICLR)) on consumer GPUs, plus extensions.

| Result | |
|---|---|
| Token-level ReDeEP, Llama-2-7B (paper's setting) | AUC 0.739 vs. 0.7325 in the paper |
| Chunk-level ReDeEP, Llama-2-7B, leakage-free | 0.731 — identical to the authors' own logged scores |
| Six LLaMA-family models (1.1B–13B) on RAGTruth | ReDeEP beats perplexity and LN-Entropy on all six; best Llama-2-13B (0.801) |

## Original notes

Reproduces the core method of "ReDeEP: Detecting Hallucination in
Retrieval-Augmented Generation via Mechanistic Interpretability"
(Sun et al., ICLR 2025) on the RAGTruth benchmark, scoped to run on
CPU-only hardware, plus a robustness-testing extension.

## Layout

- `redeep/mechanistic.py` — Copying Head Score, External Context Score
  (ECS), Parametric Knowledge Score (PKS), computed via forward hooks on
  any LLaMA-architecture HF model (TinyLlama, Llama-2, Llama-3, ...).
- `redeep/detect.py` — ReDeEP(token) detector: selects Copying Heads /
  Knowledge FFN layers, fits a logistic regression over the decoupled
  covariates, reports AUC/PCC/Acc/Rec/F1.
- `redeep/aarf.py` — AARF intervention (amplify Copying Heads, damp
  Knowledge FFNs at decode time) for hallucination mitigation.
- `redeep/robustness.py` — **extension**: feeds the model deliberately
  wrong/irrelevant retrieved context and checks whether ECS/PKS still
  behave sensibly (tests whether the signals track "faithfulness to
  context" vs. secretly tracking "matches world knowledge").
- `redeep/data.py` — loads/merges RAGTruth's `response.jsonl` +
  `source_info.jsonl` into (prompt, response, label) triples.
- `redeep/llm_judge.py` — black-box LLM-as-judge detectors (GPT via
  OpenAI / GitHub Models / Groq, Gemini, local LLaMA).
- `scripts/run_pipeline.py` — end-to-end: load data → score with a
  backbone model → fit detector → report metrics (single split + k-fold CV).
- `scripts/run_llama_family.sh` — the four-backbone LLaMA sweep below.
- `scripts/run_robustness.py` + `scripts/robustness_numeric_subset.py` —
  the robustness extension.
- `scripts/run_judges.py` — GPT / Gemini / LLaMA judge baselines.
- `scripts/summarize.py` — collects everything into `data/RESULTS.md`.

## Results (RTX 4050 Laptop 6GB, Windows 11)

Full tables with std/PCC/F1 are regenerated into `data/RESULTS.md` by
`scripts/summarize.py`. Setting = the paper's: RAGTruth **test** split,
responses generated by **llama-2-7b-chat** (415 after the length cap),
5-fold stratified CV.

| Backbone | ReDeEP AUC | Perplexity AUC | LN-Entropy AUC |
|---|---|---|---|
| TinyLlama-1.1B-Chat | **0.771** | 0.656 | 0.686 |
| Llama-3.2-1B-Instruct | **0.744** | 0.649 | 0.646 |
| Llama-3.2-3B-Instruct (4-bit) | **0.727** | 0.654 | 0.663 |
| Llama-2-7B-chat (4-bit) | **0.739** | 0.627 | 0.670 |
| *Paper, Llama-2-7B-chat* | *0.7325* | | |

- The Llama-2-7B reproduction (0.739) matches the paper (0.7325).
- ReDeEP beats both uncertainty baselines on every backbone by 0.06–0.11 AUC.
- Detection quality is roughly flat in backbone size (1.1B to 7B).

### Extension: robustness under corrupted retrieval

Same response, context swapped for an **irrelevant** passage or a copy
with **numbers corrupted**:

| Backbone | Condition | Mean ReDeEP score | Shift vs. accurate |
|---|---|---|---|
| TinyLlama-1.1B | irrelevant | 0.84 | +0.32 (p≈1e-26) |
| TinyLlama-1.1B | numbers corrupted | 0.53 | +0.005 (p=0.40, n.s.) |
| Llama-2-7B | irrelevant | 0.77 | +0.25 (p≈1e-24) |
| Llama-2-7B | numbers corrupted | 0.51 | **−0.010** (p≈6e-6) |

ReDeEP reliably detects *topically unsupported* responses but is **blind to
factual contradictions**. When the context's numbers are changed so that a
response no longer agrees with it, the score does not rise. For Llama-2-7B
it actually falls, and the Copying-Head signal (ECS) *increases*. This
holds on the 122 responses that state a contradicted number. The
interpretation is that ECS measures whether the response is *about* the
retrieved passage (semantic alignment of hidden states), not whether it
*agrees* with it.

### Black-box judges

| Judge | AUC | Recall | F1 |
|---|---|---|---|
| Llama-3.2-3B-Instruct (local, prompted) | 0.523 | 0.085 | 0.151 |

A prompted 3B judge is near chance. It answers "no hallucination" for
almost every response, catching only 8.5% of hallucinations. Reading the
same model's internals (ReDeEP on Llama-3.2-3B, AUC 0.727) does far
better than asking it. The GPT and Gemini rows need an API key (free
options below); `scripts/summarize.py` adds them to `data/RESULTS.md`
automatically.

| Method | AUC | PCC | Acc | F1 |

| ReDeEP(token) | 0.870 | 0.758 | 0.867 | 0.833 |
| Perplexity baseline | 0.926 | — | — | — |
| LN-Entropy baseline | 0.704 | — | — | — |

Both signals clearly separate hallucinated/truthful responses, confirming
the mechanistic pipeline is producing real signal. Perplexity edging out
ReDeEP here (opposite of the paper's Table 1) is most likely noise from a
15-example test split -- needs a bigger run to confirm either way.

Pipeline is now GPU-ready: `--device cuda --dtype float16` (auto-detected
if a CUDA GPU is present). `scripts/modal_run.py` is an **untested**
scaffold for running on a rented GPU via modal.com if the local GPU isn't
enough (e.g. Llama-2-13B) -- verify against your installed `modal` CLI
version before relying on it.

## Status / plan

1. **Backbone for fast iteration**: TinyLlama-1.1B-Chat (LLaMA
   architecture — RMSNorm/RoPE/SwiGLU — so the paper's formulas transfer
   exactly; small enough for CPU).
2. **Paper-faithful reproduction**: swap in `meta-llama/Llama-2-7b-chat-hf`
   / `Llama-2-13b-chat-hf` once HF gated access is set up (needs the
   user to accept Meta's license on huggingface.co and run
   `hf auth login`). Same code, only `--model` changes. Expect much
   longer runtimes on CPU — plan to run on a small, length-capped subset.
3. **Black-box baselines (GPT-4o / Gemini)**: prompt-based detectors
   (Prompt / ChainPoll / RAGAS-style) implemented as API calls, gated on
   `OPENAI_API_KEY` / `GEMINI_API_KEY` being set — used only as
   external-judge comparisons, not for mechanistic scoring (closed
   models don't expose internals).
4. **Extension**: robustness sweep (`redeep/robustness.py`) — accurate
   vs. irrelevant vs. numerically-corrupted retrieved context, same
   response, tracking how ECS/PKS shift. This is the novel contribution
   for the paper/presentation beyond reproducing ReDeEP itself.

## Running

```
cd redeep
../deepLenv/bin/python scripts/run_pipeline.py \
    --model TinyLlama/TinyLlama-1.1B-Chat-v1.0 \
    --n_per_class 30 --max_len 768
```

Results cache to `data/scores_<tag>.npz` so repeated runs (e.g. tuning
`--n_copying_heads`) don't require rescoring.
